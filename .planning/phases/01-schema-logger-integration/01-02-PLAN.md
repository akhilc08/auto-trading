<objective>
Wire the `MotherDuckLogger` (from Plan 01) into `OrderManager` and `runner.py` without touching any strategy file. `OrderManager` gains three new optional constructor params (`md_logger=None`, `strategy_name=""`, `account_name=""`) and calls `md_logger.log_order()` after each successful submission in all five order methods (buy, sell, short_sell, buy_to_cover, close_position). `runner.py` constructs the logger only when `MOTHERDUCK_TOKEN` is present, passes it (plus strategy/account names) to `OrderManager`, and wraps `run_cron`/`run_stream` in a `try/finally` that snapshots positions + portfolio and polls Alpaca for fills on exit.

Per RESEARCH.md Pitfall 1: `run_cron()` runs `BlockingScheduler.start()` forever, so the snapshot/fill-poll block only fires on process exit (SIGINT/SIGTERM). The `try/finally` matches the INTEG-04/05 wording ("after run_cron returns") and keeps `scheduler.py` untouched.

Purpose: Every order from every strategy is logged, and snapshots are written after each run — all changes confined to `core/` and `runner.py`.
Output: edits to `core/order_manager.py` and `runner.py`; new `tests/test_order_manager_logging.py`.
</objective>
