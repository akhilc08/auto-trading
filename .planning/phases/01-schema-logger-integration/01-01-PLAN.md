<objective>
Create the `MotherDuckLogger` class that owns all MotherDuck schema and write logic, and pin the `duckdb` dependency. This is the data-pipeline foundation for the entire v1.0 milestone — the schema columns defined here cannot be retrofitted later (per STATE.md blocker).

The logger connects to MotherDuck via the `MOTHERDUCK_TOKEN` service-account token, runs idempotent `CREATE TABLE IF NOT EXISTS` DDL for all 4 tables on construction, and exposes five write methods used by the integration plan (Plan 02). All Alpaca SDK numeric fields are strings and must be cast to float; all SQL uses parameterized `?` placeholders.

Purpose: A single, tested choke point for every MotherDuck write, with stable schema from day 1.
Output: `core/motherduck_logger.py`, `tests/test_motherduck_logger.py`, `duckdb==1.5.2` added to `requirements.txt`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → process | `MOTHERDUCK_TOKEN` enters via environment variable; never hardcoded or logged |
| Alpaca SDK → DuckDB | Order/Position/Account field values (untrusted external data) cross into SQL writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | MOTHERDUCK_TOKEN handling | mitigate | Read token only via `os.environ.get`; never write token to any log line or commit. Logger logs strategy/order IDs only. (ASVS V2) |
| T-01-02 | Tampering | DuckDB write methods | mitigate | All `con.execute` calls use parameterized `?` placeholders for SDK/user data; no f-string SQL. (ASVS V5) |
| T-01-03 | Tampering | Numeric field casts | mitigate | Cast all Alpaca string fields via `float()` with None guards before insert/arithmetic; prevents silent type corruption in DECIMAL columns. |
| T-01-SC | Tampering | pip install duckdb==1.5.2 | accept | `duckdb` audited `[OK]` in RESEARCH.md Package Legitimacy Audit (PyPI, ~6yr, very high downloads, github.com/duckdb/duckdb). No checkpoint required. |
</threat_model>
